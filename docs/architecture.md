# Architecture & Design Rationale (Page Flow)

本文書は、Obsidianプラグイン「Page Flow (`obsidian-page-flow`)」の設計思想、アーキテクチャ、および「Why（なぜそのように設計・意思決定したのか）」を永続化するドキュメントです。

---

## 1. 背景と解決する課題 (Motivation & Why)

### 背景: LLMによるノート急増とトリアージ負荷
大規模言語モデル（LLM）や自動化パイプラインの普及に伴い、Obsidian Vault内に「まだ確認していないノート（未読・未整理の下書きやAI要約・収集ノート）」が大量に蓄積する問題が生じています。

### 既存の課題と摩擦 (Friction)
1. **画面スクロールの摩擦**: 縦に長いノートを少しずつマウスやトラックパッドでスクロールしながら読むのは手首と集中力に負荷がかかる。
2. **ファイル切り替えの摩擦**: ノートの末尾まで読んだ後、ファイルエクスプローラーやクイックスイッチャーを開いて「次のノート」を探して開く操作のコンテキストスイッチが大きい。
3. **既存プラグインの限界**:
   - `Neighbouring Files` や `Quick Explorer`: 「次のファイルを開く」機能はあるが、ノート内のスクロール体験とは連動していない。
   - `PageMode`: マウスホイールによる無限スクロール寄りであり、キーボード中心の「画面送り → 次ファイル」という明示的な進行ステップには最適化されていない。

## 2. コア設計思想 (Core Design Principles)

### ① 1キーで完結する「ハイブリッド・ページ送り」
RSSリーダー（Feedly等）や電子書籍ビューアのように、単一のホットキー（例: `Alt + Space`）をテンポよく押すだけで、
1. ノート内を画面単位でスクロール送り
2. 最下部に達したら自動で同一フォルダ内の「次のファイル」を開く
という一連の閲覧・検品フローをキーボードから手を離さずに完結させます。

### ② 単機能コマンドの独立提供
ハイブリッドコマンド（`Scroll or Next File`）に加え、純粋なスクロールコマンド（`Scroll Page Down`）と純粋なファイル移動コマンド（`Go to Next File`）を独立して提供します。
これにより、ユーザーが自分のユースケースに合わせて任意のホットキーを柔軟にマッピングできます。

### ③ 対称的な逆方向ナビゲーション
前のファイルに戻る（`Scroll Up or Previous File`）場合、直前のファイルを開くだけでなく、**「ファイルの最下部（Bottom）を表示した状態で開く」** ように設計されています。これにより、過去のノートを末尾から遡って読み返す体験が自然に成立します。

## 3. モジュール構成と責務分離 (Module Architecture)

```
src/
├── types.ts          # 設定およびドメイン型定義
├── settings.ts       # 設定データモデル、デフォルト値、設定タブUI
├── scroller.ts       # Viewportスクロール量計算、末尾/先頭到達判定
├── navigator.ts      # フォルダ内ファイル一覧取得、ソート、次/前ファイルの解決
└── main.ts           # プラグインエントリーポイント、コマンド登録、ライフサイクル
```

### `scroller.ts` (スクロール・境界判定モジュール)
- **Reading View と Live Preview / Edit View の抽象化**:
  - Reading View: `.markdown-preview-view`
  - Edit View: `.cm-scroller`
- **スクロール量の計算**:
  - `container.clientHeight * (scrollPercentage / 100)`
  - デフォルト 85% の移動量により、前の画面の末尾15%が残り、視線の連続性を維持。
- **スマート連打キューイング & 連打加速物理エンジン (Smart Queued Smooth Scroll with Dynamic Acceleration)**:
  - **所要時間（Duration）の自由調整**: デフォルト 280ms（100ms〜1,000ms で調整可能）。流し読みしやすいゆったり速度までカバー。
  - **イージング（加減速カーブ）の固定**:
    - `easeInOutCubic` を標準採用。初速の急発進ショックを排除し、マイクロスタッターや目の疲労を最小化。
  - **動的連打加速（Dynamic Chained Acceleration）**:
    - スクロール時間を長く（例: 600ms）設定している場合でも、ユーザーがキーを連打した際は「飛ばしたい」という意図を検知し、アニメーション時間を指数減衰で動的に圧縮：
      $$D = \max\left(D_{\text{min}},\; D_{\text{base}} \times 0.65^k\right)$$
      （$k$: 連打回数、$D_{\text{min}}$: 最速キャップ 150ms）
    - 単発押しでは設定通りのゆったり速度で流れ、連打時は即座にサクサク超高速移動に切り替わる。
    - キーを離して停止すると連打カウント $k$ は即座に 0 へリセット。
  - **キュー上限キャップ**:
    - 前のアニメーション中にキーを連打した際、目標位置（Target）を正確に累積加算。最大 2.5 画面分（Viewport 高の 2.5 倍）でキャップし、暴走を防止。
- **CodeMirror 6 の仮想スクロール（高さ急変）への耐性**:
  - 長大ノートの中間地点等で CodeMirror 6 が行高さを再測定し全体の高さが急変（+300px等）しても、エディタの強制ブレーキに負けず、指示された移動量を確実に運び切る。
- **境界判定**:
  - 下方向到達: `currentOrTargetScrollTop + clientHeight >= scrollHeight - threshold`
  - 上方向到達: `currentOrTargetScrollTop <= threshold`

### `navigator.ts` (ファイルナビゲーションモジュール)
- カレントファイルの親フォルダ（`file.parent`）から Markdown ファイル（`TFile` かつ `extension === 'md'`）を抽出。
- 指定されたソート規則（ファイル名昇順/降順、作成日時新しい/古い順、更新日時新しい/古い順）でソート。
- カレントファイルの次または前のインデックスを特定。
- 終端（先頭/末尾）時の挙動（ループ or 通知）を制御。

## 4. モバイルおよびクロスプラットフォーム互換性

- Node.js組み込みモジュール（`fs`, `path`, `child_process` 等）への依存を排除。
- すべて標準 Web API および Obsidian 公式 API（`app.workspace`, `app.vault`）で完結。
- デスクトップ環境・モバイル環境（iOS/Android）の両方で完全動作する設計。
